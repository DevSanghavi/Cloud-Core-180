# Day 174 — Applications: Send 10 more applications

## Goal

Send 10 more tailored applications for real entry-level cloud and DevOps opportunities. Dev completes every company, role, link, and application status by hand; no fake companies or invented experience.

## Application Rules

- Apply only to real roles matching Junior DevOps, Cloud Support, Site Reliability, Cloud Operations, or adjacent entry-level roles.
- Target Gujarat, Mumbai, Pune, and remote India.
- Read each job description before applying.
- Tailor the resume and cover note to the specific role.
- Use only verified project experience and skills.
- Do not include `.env`, credentials, account IDs, or private keys.
- Record every application in the tracker, including rejections or closed roles.

## Tailoring Checklist

Before sending each application, confirm:

1. The role is entry level, internship, associate, or explicitly open to freshers.
2. The location is Gujarat, Mumbai, Pune, or remote India.
3. The job description requires at least two skills from the project stack.
4. The resume highlights the most relevant projects and tools.
5. The cover note names the exact company and role.
6. The cover note includes one specific reason for applying.
7. The cover note includes two relevant skills from the job description.
8. The GitHub repository links are included.
9. No confidential information or credentials are included.
10. The application is recorded in the tracker immediately after submission.

## Quality Control

Do not send an application if:

- The role requires Kubernetes, advanced Terraform modules, or production on-call experience that the posting does not explicitly welcome for freshers.
- The company or role cannot be verified.
- The application requires fabricated experience, metrics, or employment history.
- The job description has no clear connection to cloud, DevOps, support, reliability, Linux, or infrastructure work.

## Rules

- Do not invent experience, employers, metrics, salaries, or company names.
- Do not include `.env`, credentials, account IDs, or private keys in any application material.

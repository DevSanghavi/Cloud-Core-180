# Day 171 — Job Search Strategy: Target "Junior DevOps", "Cloud Support", and "Site Reliability" roles

## Goal

Create a focused job-search strategy and tracker for entry-level cloud and DevOps roles. Dev fills real companies, roles, links, and application details by hand; no fake companies or invented experience.

## Positioning Statement

Use this statement in LinkedIn messages and application notes:

```text
I am a cloud and DevOps fresher with hands-on projects in Terraform, AWS, Docker, Nginx, GitHub Actions, Linux, monitoring, and CI/CD. I built and operate a Terraform-provisioned AWS environment with a Flask application, GitOps-style production and staging deployments, rollback automation, CloudWatch alarms, SNS alerts, and daily S3 log backups. I am seeking an entry-level Cloud, DevOps, Cloud Support, or Site Reliability opportunity where I can contribute to reliable cloud operations.
```

## Daily Job-Search Routine

1. Search three role families for 30 minutes.
2. Save five relevant jobs.
3. Read each job description and identify matching skills.
4. Tailor the resume only where the job description requires it.
5. Send applications only for roles matching the target locations and experience level.
6. Record every application in the tracker.
7. Send one polite LinkedIn connection request or message to a relevant recruiter or engineer.
8. Review rejected or closed roles and improve the next application.

## Role Fit Rules

Apply when the job requires at least two of the following:

- Linux fundamentals.
- AWS cloud services.
- Terraform or infrastructure as code.
- Docker or containers.
- CI/CD or GitHub Actions.
- Nginx or reverse proxies.
- Monitoring or observability.
- Git and Git Flow.
- Troubleshooting or incident response.
- SQL or relational databases.

Skip a role when it requires skills not yet demonstrated, such as Kubernetes, advanced scripting, or production on-call experience, unless the posting explicitly welcomes freshers or interns.

## Rules

- Dev sends all applications and messages by hand.
- Use only real companies, roles, links, and application statuses.
- Do not invent experience, employers, metrics, salaries, or company names.
- Do not include `.env`, credentials, account IDs, or private keys in any application material.
